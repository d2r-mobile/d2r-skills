# 参考图展示模式

以下模式提炼自三类游戏 UI 参考：功能弹窗、收藏列表改版、局部三态对照。它们是表达设计决策的方法，不是把所有项目都做成同一种美术风格的模板。原始图片不随 skill 分发，使用时读取用户当次提供的素材。

## A. 完整场景中的功能弹窗

适用于已有界面新增操作、筛选、合成或说明入口。

- 保留外层导航、装备区或产品框架，让用户知道功能发生在哪里。
- 弹窗建立标题、内容组、操作和底部辅助提示的层级。
- 将“可执行”和“缺少条件”的条目放在同一画面时，操作状态与原因必须对应。
- 缺少材料用文字和颜色共同表达；不能只变红。不要为不可执行项画出可点击的主操作。
- 对话框的遮罩、边框、按钮材质与宿主一致，但避免半透明背景降低文字可读性。
- 需要解释机制时，提供独立说明，不让长段产品解释挤占弹窗。

**可以借鉴**：上下文、信息分组、就地操作与不可执行原因。
**不能盲抄**：示例中的游戏规则、模糊字体、具体物品名称或数值。

## B. 原界面中的列表与收藏系统改版

适用于套装收藏、图鉴、库存、资源管理与列表页二开。

- 稳定的行高和列对齐：名称/完成度、条目槽位、动作或状态保持固定关系。
- 区分“当前拥有”“曾经收录但已不在库”“从未获得”“整组已完成”。状态命名服从实际业务，而非凭美术猜含义。
- 有色边框配合计数、状态文字或标记。完整行高亮不能盖过主要内容。
- 筛选、分页、总数与当前页信息相互一致。示例数据也应自洽。
- 详情触发区域和存入/取出动作在交接说明里写清，避免开发误把整行都当成同一种操作。
- 对比图保留周围未改动的界面；复杂说明放在图外边栏，并与具体区域对应。

**可以借鉴**：把信息架构、状态语义和原有视觉框架同时呈现。
**不能盲抄**：拥挤行密度、色彩作为唯一编码或未经确认的业务规则。

## C. 同一局部的三态对照

适用于 HUD、角标、剩余次数、按钮状态等小范围改动。

推荐排列：**现状 → 新状态可用 → 次数用尽**。用户指定其他状态时按其要求。

- 每格使用相同裁切、显示比例、背景、按钮坐标和尺寸，图外标题高度一致。
- 角标与数量各自有固定锚点、边距和字号，不挤占中心图标。
- 例如右上显示 `II`、右下显示 `9`；耗尽后按钮变灰并显示 `0`。在实际制作约束里声明耗尽时是否仍保留 `II`，不要让生成器自行决定。
- “灰”仍应看得清楚轮廓、图标和零值。禁用态不是降低到不可辨识。
- 原图中无关的按钮、背景和符号不能随着状态变化。
- 局部图用于看细节，必要时补一张完整场景图确认位置；无需为一个角标重新设计全屏。

**可以借鉴**：用最少画面讲清变化和交互状态。
**不能盲抄**：把多状态拼成一张实际产品界面，或把图外说明做成界面标题。

## 无既有界面的需求脑洞

没有底图时，先指定目标任务与设备，再选一个合理的设计语言。不同方向应体现布局、信息优先级或交互机制的区别；仅改变配色不算新的方向。比较时使用同一任务和同一组数据，避免一张塞满内容、另一张只留装饰导致无法判断。
